# Agent Roles and Adaptive Behavior

## Supervisor

The Supervisor inspects the shared blackboard and proposes only legal destinations. Its LLM selects the next action based on current evidence and records a rationale. This allows it to request another writing round, skip criticism for a trivial function, trigger mutation testing, send survivors to the analyst, or stop with a report. The offline priority policy exists only so the repository can be smoke-tested without credentials, and the trace labels it as a fallback.

## Code Analyst

The Code Analyst runs the AST parser, discovers the selected top-level function, summarizes parameters and structure, estimates decision complexity, and requests behavioral risks from the LLM. It distinguishes syntactic facts from inferred behavior and uncertainty.

## Adversary

The Adversary is not just a general edge-case checklist. It reads classified survivors and creates new cases intended to distinguish the original behavior from the surviving mutant. Its outputs include a target description, expected behavior when supportable, and priority.

## Test Writer

The Test Writer turns source analysis and edge cases into pytest code. It executes that code through the subprocess runner and makes up to two self-repair attempts when pytest fails. The separate Critic can ask for a further revision even when the current test module passes.

## Test Critic

The Critic checks assertion specificity and whether the tests are likely to fail for a realistic wrong implementation. It should reject vacuous checks and provide actionable revision instructions. If the LLM critic is unavailable, the heuristic fallback fails closed rather than pretending to provide a semantic review.

## Mutation Analyst

The Mutation Analyst reviews mutants that survived. It must distinguish likely genuine gaps from likely equivalent mutants and uncertain cases. If no confident classification is possible, it must leave the case uncertain instead of claiming that the mutant is equivalent.

## Reporter

The Reporter produces a final factual report with pytest status, mutation engine/status, criticism, unresolved gaps, and errors. A real trace is generated by runtime events and accompanies the report.

## Negotiation evidence to capture in the demo

1. Test Critic rejects a weak or incomplete test and sends concrete revision instructions to Test Writer.
2. Mutation Analyst classifies a surviving mutant as a gap, which Adversary translates into a targeted case.
3. Supervisor notices a mutmut timeout/crash, records it, and selects a recovery path or Reporter.
4. A simple function can take a shorter route than a branch-heavy function. Show this with genuine system-generated traces, not manually edited trace lines.
